# K2SO 0.37.5 — Drop `:<agent_name>` from canonical session key

**Status:** plan, 2026-05-06
**Closes:** C3PO `5c80bef1` (SMS Bridge / nsi-checkin)
**Estimate:** 5–7 hours focused work
**Author:** rosson@alakazamlabs.com (with implementation help)

## North star

Post-0.37.0 unification, every workspace has at most ONE agent. The agent's name is metadata about the session, not part of its address. Drop the `:<agent_name>` suffix from the canonical workspace+agent session key everywhere it appears so the renderer never computes a name and the SMS Bridge `5c80bef1` bug class is structurally impossible.

## What "after" looks like

| Address shape | Meaning | Owner |
|---|---|---|
| `<project_id>` (raw UUID) | Canonical workspace+agent session in `v2_session_map` | daemon |
| `tab-<terminal_id>` | Cmd+T ad-hoc tab | renderer-driven |
| `terminal-<short>` | Background spawn without an agent | daemon |
| `agent-chat:<pid>` | `workspace_sessions.terminal_id` SQL value | daemon |
| `agent-chat:wt:<workspace_id>` | Worktree-scoped chat (unchanged) | core |
| `agent-chat:<pid>:<agent>:hb:<schedule>` | Per-heartbeat session id (unchanged) | core |
| `pending_live/<sanitized_pid>/` | Wake-queued signals dir | daemon |

The canonical session key for a workspace IS the workspace's identity. Display name lookup is a separate read against AGENT.md via the existing `agent_display_name(project_path)` helper (already shipped 0.37.4 Phase A).

### Heartbeat note (important)
There are NO heartbeat sessions registered under separate `heartbeat:<pid>:<schedule>` keys today. Heartbeat fires register under the workspace's primary-agent canonical key with `--session-id` pinning. After Phase B they register under bare `<pid>` — same slot the chat tab uses. That's correct: a heartbeat fire IS the workspace's canonical session, just with `--print` semantics. Don't introduce new heartbeat keying in 0.37.5.

### Acceptance for Phase B alone
0.37.5 daemon + 0.37.4 renderer = degraded but functional via the spawn.rs:228 fallback (renderer's `<pid>:<agent>` is parsed as `pid`, registered under `<pid>`).

## Phase D — Daemon: boot-time SQL + v2_session_map migration

### Surfaces touched

**SQL migration:**
- `crates/k2so-core/drizzle_sql/0042_canonical_key_drop_agent_suffix.sql`:

```sql
UPDATE workspace_sessions
SET terminal_id = printf('agent-chat:%s', project_id)
WHERE terminal_id IS NOT NULL
  AND terminal_id LIKE 'agent-chat:%'
  AND terminal_id NOT LIKE 'agent-chat:wt:%'
  AND terminal_id NOT LIKE 'agent-chat:%:hb:%';
```

**Code migration:**
- `crates/k2so-daemon/src/main.rs` — add `migrate_workspace_sessions_terminal_id()` boot helper.
- `crates/k2so-daemon/src/main.rs` — add `migrate_v2_session_map_keys_to_bare_pid()` boot helper:
  1. Snapshot v2_session_map.
  2. For each `<uuid>:<rest>` key whose project_id resolves to a real `projects` row, atomically re-key to bare `<uuid>`.
  3. If both shapes exist (race), keep bare-keyed one.
- Order: BEFORE `boot_sweep_ensure_canonical_sessions()`.

### Risks
- **Cross-version mismatch**: 0.37.5 daemon + 0.37.4 renderer. Phase B fallback at spawn.rs:228 handles this.
- **Daemon restart**: 0.37.5 installer SHOULD trigger daemon restart. If it doesn't, the in-memory migration is a no-op (because the daemon didn't boot), and stale `<pid>:<agent>` entries can persist. **Mitigation: confirm installer restarts daemon, or add `k2so daemon restart` post-install hook.**

### Acceptance
- After daemon boot under 0.37.5, every `workspace_sessions.terminal_id` is one of: `agent-chat:<pid>`, `agent-chat:wt:<wid>`, `agent-chat:<pid>:<agent>:hb:<schedule>`, NULL.
- v2_session_map: every canonical entry keyed on raw UUID; no `<uuid>:<name>` canonical entries.
- pending_live/: no `<sanitized_pid>_<agent>/` dirs.

## Cross-phase acceptance

### Primary — SMS Bridge `5c80bef1` regression test (manual)
1. Enroll workspace: `mkdir foo-checkin && cd foo-checkin && k2so workspace open . && k2so mode custom`
2. Write `.k2so/agent/AGENT.md` with `name: scout`
3. `ensure_canonical_session` creates one entry in v2_session_map keyed on UUID (no `:scout`)
4. `workspace_sessions.terminal_id` = `agent-chat:<pid>` (no `:scout`)
5. `k2so msg foo-checkin "hello" --wake` injects in canonical session
6. Open Tauri, click pinned chat tab — spawn body has `agent_name: <pid>` (raw UUID), no `:__lead__` or `:scout`
7. `lookup_by_agent_name(<pid>)` returns `reused: true`
8. `k2so agents running` shows ONE claude process
9. Subsequent `k2so msg --wake` lands in SAME PTY
10. SMS replies continue through subsequent webhook fires

### Regression
- `k2so msg <ws> <text> --wake`: works
- `k2so msg <ws> <text>` (default inbox): works
- Heartbeat fire with `--session-id` pinning: works, lands in canonical session
- Cmd+T ad-hoc tab: works, registers under `tab-<terminalId>`
- Worktree chat tab: works, registers under bare worktree agent name
- Refresh button: kills `<pid>` PTY, spawn-on-mount resurrects
- Multi-workspace name collision: two workspaces both `name: scout` — each has own canonical session under own UUID

### Migration
- Boot daemon with `agent-chat:<pid>:<agent>` SQL rows: after migration, all `agent-chat:<pid>`
- Boot daemon with `pending_live/<sanitized_pid>_<agent>/` queued signals: signals in `pending_live/<sanitized_pid>/`, drained on next spawn
- In-memory v2_session_map migration: live sessions don't drop on re-key
